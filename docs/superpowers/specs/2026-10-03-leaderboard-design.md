# 排行榜设计

**日期：** 2026-10-03
**状态：** 已确认，等待实现计划

## 目标与边界

在“我的”页面增加排行榜入口，为用户展示会随学习行为变化的背诵排名。第一版使用 Supabase，保持客户端离线可用、请求量低，并允许排行榜显示存在数分钟延迟。后续替换为 Cloudflare 时，页面和本地统计逻辑不应改变。

排行榜只包含下列会变化的指标：

1. **累计背诵次数**：已保存的背诵记录总数。
2. **已背诵不同经节数**：至少完成过一次的不同经节数量。
3. **最高连续背诵天数**：历史最高连续天数。

注册时间、注册时长、创建日期等不会随学习行为变化的资料不参与排名。第一版不上传背诵原文、逐次作答结果、计划内容、笔记或设备硬件标识。

## 身份与显示名

首次需要云同步时，客户端使用 Supabase 匿名登录，匿名账户的 `auth.users.id` 是服务器端用户主键。

显示名的优先级如下：

1. 用户在“我的”页面填写的 `profile_name`；
2. 默认名 `设备型号 · 设备代号`，例如 `小米 15 · 7K3M9P`。

设备型号仅是人类可读的前缀。设备代号由应用首次启用时产生的随机安装标识派生，并同时保存在本机与用户云档案中；不读取 IMEI、序列号、MAC 地址或其他硬件唯一标识。卸载后重装将创建新的匿名账户与默认名。用户随后可通过现有个人名称设置覆盖默认名。

## 客户端架构

新增 `leaderboard` feature，按现有领域、应用、数据、展示层组织：

- `domain`：定义 `LeaderboardMetric`、排行榜条目、个人排名快照和 `LeaderboardGateway` 接口。
- `application`：从 SQLite 已有 `RecitationSummary` 与 `LearningStats` 生成汇总快照；管理脏标记、15 分钟上传节流、5 分钟读取缓存和 Riverpod 状态。
- `data`：Supabase 实现、匿名身份初始化、SQLite 缓存与本地设置存储。
- `presentation`：排行榜页面及“我的”页入口。

页面和应用层只依赖 `LeaderboardGateway`。Supabase 版本作为默认实现；未来 Cloudflare Worker 实现同一接口即可替换请求后端，不改变 UI、缓存或本地指标计算。

## 同步与缓存

完成一条背诵记录时，客户端只把排行榜状态标记为待同步；不立即请求网络。应用在下列时机尝试同步：

- 脏数据产生满 15 分钟后；
- 应用启动或从后台恢复时，且上次成功同步距今至少 15 分钟；
- 用户在排行榜页主动下拉刷新。

每次同步将三项完整汇总写入一次 Supabase RPC。网络失败时保留脏标记，下一次合适时机重试；不影响本地背诵与统计。

排行榜查询结果按指标各自缓存 5 分钟。打开页面优先显示本地缓存，缓存过期后在后台刷新；用户主动刷新忽略缓存。每次读取只请求一个 RPC，它同时返回前 50 名以及当前用户在该指标下的排名，避免前端额外查询个人排名。

## Supabase 数据模型与访问控制

数据库仅保存汇总行：

- `public.leaderboard_profile`：`user_id`、`display_name`、`install_alias`、`updated_at`。
- `public.leaderboard_score`：`user_id`、`total_sessions`、`unique_verses`、`max_day_streak`、`updated_at`。

二者均以 `user_id` 作为主键并引用 `auth.users.id`，并启用 RLS。匿名认证用户只能读取和更新自己的两张表行；榜单数据不直接开放表查询。

提供两个安全边界明确的函数：

- `submit_leaderboard_snapshot(...)`：以 `auth.uid()` 确定写入者，只允许写自己的汇总值与显示名；汇总数字不得为负，累计指标与最高连续天数不得倒退。
- `get_leaderboard(metric, limit)`：只接受三种白名单指标，返回按分数降序、最后更新时间升序排序的前 50 名与调用者当前名次。

函数使用最小授权：撤销 `PUBLIC` 默认执行权，仅授予 `authenticated`；若使用 `SECURITY DEFINER`，固定空 `search_path`、显式限定 `public` 表名并检查 `auth.uid()`。第一版是客户端汇总上传的社区自报榜，不能防止被修改过的客户端伪造异常高分；不把它用于奖励、权限或经济价值。

## 界面与异常状态

“我的”总览增加一张“排行榜”卡片，显示三项中的个人最佳摘要、最近更新时间和入口。排行榜页提供三项指标切换，列表显示名次、显示名、数值与当前用户高亮行。

无网络或 Supabase 未配置时，入口仍可打开：显示本地个人指标、上次缓存榜单（如有）以及“暂无法更新”的轻量提示。匿名登录或同步失败均不能阻塞背诵流程。没有任何榜单数据时显示空状态而不是错误。

## 配置与部署

Supabase URL 和 publishable/anon key 通过构建期 `--dart-define` 注入，不进入仓库或移动端源代码。缺少配置时，`LeaderboardGateway` 使用离线实现并保持页面可用。

数据库变更放入 Supabase migration：建表、索引、RLS 策略、函数、函数权限和测试查询。发布前执行 Supabase 安全检查与函数验证。未来 Cloudflare Worker 需复用匿名账户令牌校验和相同的请求/响应模型。

## 测试与验收

1. 领域测试验证仅三项已确认指标可选，且本地统计值映射正确。
2. 应用测试验证 15 分钟节流、失败后保留脏标记、5 分钟读取缓存和手动刷新。
3. 数据层测试验证匿名身份、请求载荷、榜单解码与离线回退。
4. Widget 测试验证“我的”入口、指标切换、当前用户高亮、缓存/错误/空状态。
5. 数据库测试验证 RLS、指标白名单、只能更新自己的分数、累计值不可回退以及排名查询包含当前用户。

验收时，普通背诵不会为每次记录发起云端请求；无配置或离线时本地背诵与“我的”页面保持可用；榜单页能在数分钟内反映已同步的三项指标。
