# 年度灵修、笔记与数据备份设计

## 目标

为 2026 年全年灵修提供由 `kobe24o/bible-recite-plans` 发布、可离线缓存的逐日经文安排。当天灵修只在“今日任务”展示；用户可在计划页浏览全年、从今天开始查看、阅读高亮经文并记录笔记。用户生成的学习数据可导出为一个文件，并能在另一台设备上合并或完整恢复。

## 范围与非目标

- 灵修日程仅有日期和一个或多个经文范围；没有题目、引言或祷告提示。
- 灵修阅读不创建背诵、答题、艾宾浩斯或勋章进度，也不会被这些数据混入。
- 导出包含用户生成的计划、完成状态、背诵与答题记录、勋章、灵修笔记和普通设置；不包含圣经包、语音模型、云端日程缓存或模型 API 密钥。
- 2026 日程源自用户提供的 365 天清单；后续年份和修订由发布仓库追加。

## 方案选择

1. 将灵修伪装成背诵计划：可少写少量 UI，但会错误出现背诵进度和任务操作，且无法承载笔记。拒绝。
2. 使用独立的灵修清单、笔记表和备份协议：复用 HTTPS 下载、经文阅读和 SQLite 基础设施，但保持灵修和背诵的语义隔离。采用。
3. 把全年表硬编码在 App：更新必须发新版，不能满足 Git 追加更新。拒绝。

## 发布格式与同步

公共仓库根目录新增 `devotion-plans.json`，协议为 `bible-recite-devotion-plans` 版本 1：

```json
{
  "format": "bible-recite-devotion-plans",
  "version": 1,
  "revision": 1,
  "years": [{
    "year": 2026,
    "days": [{
      "date": "2026-01-01",
      "passages": [{"bookId": "EZR", "startChapter": 1, "startVerse": 1, "endChapter": 1, "endVerse": 22}]
    }]
  }]
}
```

一日可有多个经文段，段内只能在同一卷；同章整章用真实首、末节表示，以便统一阅读和校验。客户端使用与当前云端计划相同的 Gcore、Fastly、jsDelivr、GitHub Raw 回退顺序，下载体积、HTTPS 和超时限制保持一致。成功同步后缓存原始清单与修订；网络失败时继续读取上次有效缓存。清单解析必须拒绝重复日期、无效日期、无效经卷/范围，以及一年中缺失或越界的日期。

## 本机数据

SQLite 新增：

- `devotion_note(date PRIMARY KEY, content, updated_at)`：按日保存用户笔记；云端同步永不修改。
- `devotion_manifest_cache` 通过设置表保存已验证的 JSON 与版本；只有完整校验后替换。

笔记以日期为稳定身份。不同年份同月日不冲突，备份合并时以 `updated_at` 较新的内容为准；同时间戳时保留本机内容。

## 界面与阅读流程

“计划”页增加“年度灵修”卡片，显示已缓存年份、同步状态和进入入口。灵修日程为专页列表，日期连续显示；首次进入自动滚动到今天的条目并以“今天”标识。若当前年份没有日程，显示同步/离线说明。

今日页只查询今天的灵修条目并将其放在待完成任务之上。灵修没有完成按钮，点击卡片打开灵修详情。

灵修详情显示日期、每段经文和多行笔记输入框，自动保存并显示保存反馈。点经文进入既有 `PassageScreen`：

- 仅当天被安排的经节应用计划阅读的高亮样式；同章离散范围保持离散高亮。
- 跨章或跨卷日程被转换为现有 `PlanTaskChapterGroup`。每页加载完整章节，并只高亮该章内安排的范围。
- 初始显示第一段所在章节；左右滑动或现有上一章/下一章控件按安排的章节组移动，不会把未安排的中间章节当作灵修内容。

## 一键备份与恢复

“我的”页面新增“数据备份与恢复”。导出 `BibleRecite-backup-YYYYMMDD.json`，格式为 `bible-recite-user-backup` 版本 1，含显式对象数组和时间戳，而不是直接复制 SQLite 文件。导出使用现有 Android 下载通道与桌面文件选择器。

导入在解析、大小限制和版本校验成功后展示两种操作：

- **合并**：以稳定 ID 去重计划、背诵结果、答题历史、勋章与笔记；对笔记使用更新时间规则；保留本机未包含的数据。
- **完全覆盖**：单个 SQLite 事务先清空可恢复的用户表，再导入备份；失败时回滚，不留下半恢复状态。

恢复完成后刷新计划、今日、统计和个人资料 providers。任一无效记录不会绕过范围或关系校验；合并报告导入、跳过与冲突处理数。

## 验证

- 单元测试：清单解析、2026 日程的完整性和经文范围；同步缓存与网络回退；笔记的保存/读取；备份编码、合并、完全覆盖、无效版本及事务回滚。
- Widget 测试：计划页灵修入口、今日页只呈现当天条目、日程默认定位今天、笔记保存、跨章阅读的精确高亮与章节导航、恢复模式选择。
- 回归：已有计划、统计、阅读和导出测试继续通过；执行 `flutter test` 与 `flutter analyze`。
